# Project Charter — University Library Management System

## 1. Project Purpose
The purpose of this project is to plan a University Library Management System that improves how a university library manages books, members, borrowing, returns, reservations, and overdue items. The system is intended to reduce reliance on manual records and make library information easier to manage.

## 2. Project Objectives
- Organize book, copy, and member information.
- Make book availability easier to check.
- Record borrowing, due dates, and returns consistently.
- Support reservation requests.
- Identify overdue loans and show notification information.
- Prepare a clear SRS, UML diagrams, and a clickable prototype.

## 3. Project Scope
### In scope
Book catalogue management; member records; search and availability; issue/borrow; return; reservations; overdue tracking and notification status; role-based screens for members, librarians, and administrators; requirements analysis; UML modelling; and clickable UI prototyping.

### Out of scope
Complete software implementation and production deployment; live connection to university databases; online fine/payment processing; purchase of hardware; and real SMS/email delivery. These may be considered future enhancements, but they are not deliverables for the current academic project.

## 4. Main Deliverables
1. GitHub repository, README, project plan, commit history, and GitHub Issues (Assignment 1).
2. Stakeholder analysis, requirements, user stories, acceptance criteria, AI review, and SRS (Assignment 2).
3. Use-case, class, sequence, and activity diagrams with explanations (Assignment 3).
4. Clickable Figma prototype, workflow demonstration, usability feedback, and improvements (Assignment 4).

## 5. Assumptions
- The university will provide the library's rules for borrowing periods, renewals, reservations, and overdue handling.
- Librarians will maintain the accuracy of book and member records.
- Every physical copy can be tracked separately.
- Student and faculty membership details will be available through an approved process.
- Sample data will be sufficient for diagrams and prototype demonstrations.

## 6. Constraints
- The project is completed by a two-student team.
- The academic scope is analysis, modelling, and prototyping, not complete implementation.
- The work must be completed within the instructor's actual submission dates.
- The team will use available/free versions of the required tools.
- No confidential real student data will be placed in the public repository.

## 7. Success Criteria for Assignment 1
- The repository exists with the required name and README.
- The four required folders are present.
- A project scope, objectives, assumptions, and constraints are documented.
- A dated schedule/Gantt chart, WBS, responsibility matrix, and risk register are included.
- At least three meaningful commits appear in GitHub history.
- Major tasks have GitHub Issues and appropriate assignees.
- The repository can be cloned to the team computer.
